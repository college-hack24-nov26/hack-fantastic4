# Phase 1C.2A: acquisition and GPU readiness

## Data rights and acquisition state

No real images or annotations were downloaded. The [official COCO terms](https://github.com/cocodataset/cocodataset.github.io/blob/master/dataset/termsofuse.htm) grant CC BY 4.0 for annotations, while image rights belong to their Flickr copyright holders. A COCO image `license` ID alone does not establish permission for every intended use, redistribution, or commercial deployment. The template at `configs/acquisition_manifest.template.json` lists the per-image evidence needed before an image download can be approved. It is deliberately empty: no selected IDs, attribution, license basis, or checksums have been verified.

The [official download listing](https://github.com/cocodataset/cocodataset.github.io/blob/master/dataset/download.htm) identifies the 2017 train/val annotation archive (~241 MB), full train image archive (~18 GB), and val image archive (~1 GB). The Phase 1C.1 plan targets 1,500 train, 250 internal validation, and 250 held-out images. Its rough selected-image transfer estimate remains ~0.3–0.6 GB, with at least 2 GB local reserve, plus the annotation archive. These estimates have not been verified against a selected manifest.

The official annotation host `images.cocodataset.org` failed HTTPS certificate hostname checks on this laptop in both Python and Windows curl (`SEC_E_WRONG_PRINCIPAL`). We did not disable verification or substitute an unverified mirror. Consequently the official annotation contents, individual image license metadata, exact selected IDs, rights review, and download manifest are **not ready**. Before acquiring images: restore authenticated TLS access to the official host or identify a verified official distribution path; obtain annotation files; freeze the deterministic ID plan and annotation hashes; review each chosen image's rights and attribution for the intended use; then present the completed manifest for user approval. If that cannot be done, use a smaller set of images with clear permission or consented custom phone recordings. No data redistribution through Git.

## Code and GPU findings

- `model.py` sets both `weights=None` and `weights_backbone=None`; no weight loader or pretrained download is called. Model IDs are 1–5 with background 0. The loader uses RGB float CHW `[0,1]` and converts COCO pixel `xywh` boxes to pixel `xyxy`; empty images produce `(0,4)` boxes. Split planning keeps official train2017 and val2017 apart. Exact image-content duplicates still need checking once images are present.
- CUDA was available on the RTX 3050 Laptop GPU (4,294,443,008 bytes total). A bounded synthetic step measured batch 1: 3,459,986,228 bytes free before, 109,153,792 peak allocated, 132,120,576 peak reserved, 691.4 ms. Batch 2: 3,443,209,012 bytes free before, 208,537,600 peak allocated, 224,395,264 peak reserved, 261.5 ms. These are **single synthetic-step** measurements including startup effects; they do not predict training throughput, real-image memory use, or Android latency.
- Batch 1 needed BatchNorm running statistics frozen because a 1×1 feature map cannot compute statistics from one value. The current trainer does not implement that mode. **Use batch 2** for a later controlled real-data probe; remeasure peak VRAM on representative images and stop on out-of-memory.
- Training uses SGD with momentum 0.9 and loss components returned by Torchvision SSD. The DataLoader shuffles with seed 42 and drops a final incomplete batch. The code checks train/internal-validation class mappings and does not expose the held-out test set to the trainer.
- `last.pt` is the latest completed epoch and includes model, optimizer, epoch, config, class mapping, and validation AP50. `best.pt` is replaced only when internal-validation **AP50 at IoU 0.5 and score floor 0.05** improves. Training stops after two nonimproving epochs or the configured eight-epoch maximum. This metric is a simple 101-point interpolated mAP50 across classes with ground truth, **not COCO mAP 0.50:0.95**. Both checkpoints are under ignored `runs/`.
- Training resume is **not implemented**. A stopped run must be restarted; do not mistake `last.pt` for an automatic resume. The evaluation CLI runs separately and checks checkpoint category mapping. Empty predictions and empty ground truth have synthetic unit coverage. No real evaluation result exists.

## Android handoff

Model IDs: `0` background; `1` person; `2` bicycle; `3` motorcycle; `4` car; `5` chair. The Python input is RGB float CHW in `[0,1]`. The inspected Torchvision model resizes to 320×320 and normalizes each channel as `(x - 0.5) / 0.5`. Python inference returns per-image pixel `xyxy` boxes, integer IDs, and confidence scores. Android would need an agreed upright-image coordinate convention, rotation/mirroring/crop/letterbox transformations, normalization equivalence, pixel-to-contract normalized box conversion, timestamp and stale-result policy, and mock-versus-real provenance. Exported tensor layout, runtime compatibility, quantization, and device latency are not yet validated; no shared contract was changed.
